# Contribuindo para o projeto

Obrigado por se interessar em contribuir com o **VSCode Blog Viewer**! 💙

Toda ajuda é bem-vinda! Seja reportando bugs, sugerindo melhorias ou enviando pull requests.

## Como contribuir

1. **Fork** o repositório e crie uma nova branch:
   ```bash
   git checkout -b minha-contribuicao
   ```
2. Faça suas alterações e garanta que o código esteja limpo e funcional:

- Use TypeScript.
- Execute ```npm run compile``` para verificar se tudo compila corretamente.
- Mantenha o estilo de código consistente com o restante do projeto.

3. **Commit** suas mudanças com uma mensagem clara:

    ```
    git commit -m "exemplo: Adiciona melhoria na verificação de novos posts"
    ```
4. **Push** para sua branch e abra um **Pull Request**.

## Diretrizes de código

- Evite dependências desnecessárias.
- Prefira código simples e legível.
- Documente funções públicas com JSDoc.
- Teste antes de enviar.

## Reportando problemas

Se encontrar um bug ou tiver uma sugestão, abra um **issue** descrevendo:

- O comportamento esperado.
- O comportamento atual.
- Passos para reproduzir.

---

>💡  Dica: mantenha o tom colaborativo e respeitoso nas discussões. Este projeto é aberto para aprendizado e evolução conjunta.

# Contributing to the project

Thank you for your interest in contributing to **VSCode Blog Viewer**! 💙

All contributions are welcome—whether it's reporting bugs, suggesting improvements, or submitting pull requests.

## How to contribute

1. **Fork** the repository and create a new branch:
```bash
git checkout -b my-contribution
```
2. Make your changes and ensure the code is clean and functional:

- Use TypeScript.
- Run `npm run compile` to verify that everything compiles correctly.
- Keep the code style consistent with the rest of the project.

3. **Commit** your changes with a clear message:

```
git commit -m "example: Add improvement to new post check"
```
4. **Push** to your branch and open a **Pull Request**.

## Code guidelines

- Avoid unnecessary dependencies.
- Prefer simple, readable code.
- Document public functions using JSDoc.
- Test before submitting.

## Reporting issues

If you find a bug or have a suggestion, open an **issue** describing:

- The expected behavior.
- The actual behavior.
- Steps to reproduce.

---

>💡 Tip: Maintain a collaborative and respectful tone in discussions. This project is open for learning and collective growth.
